Teraz widać przyczynę wyraźniej. Sprawdziłem repozytorium VV: stopka jest już w src/main.ts, a workflow buduje aplikację Vite i wdraża katalog dist.
Pokazany przez Ciebie kod źródła strony zawiera jednak:
<script type="module" src="./src/main.ts"></script>
To źródłowy HTML, a nie wynik produkcyjnego builda Vite. Vite powinien wygenerować w dist/index.html odwołanie do zbudowanego pliku JavaScript w assets. Wdrożona strona wygląda więc na serwowaną z niewłaściwego źródła — najpewniej GitHub Pages nadal publikuje branch main z katalogu głównego, zamiast artefaktu z GitHub Actions. Sam sukces jobów build i deploy nie potwierdza, że Pages pokazuje właśnie ten artefakt.
Zrób proszę po kolei:
1. Otwórz repozytorium szeremhome/VV → Settings → Pages. W sekcji Build and deployment ustaw Source: GitHub Actions.
2. W Actions otwórz ostatni udany workflow Deploy. W kroku Sprawdzam zobacz, czy ./dist/index.html odwołuje się do pliku z assets, a nie do ./src/main.ts.
3. Sprawdź Deployments → github-pages, czy najnowszy deployment pochodzi z tego uruchomienia workflow.
4. Otwórz stronę ponownie przez Ctrl+F5. Stopka generowana w src/main.ts nie musi być widoczna w samym „Wyświetl źródło strony”, bo jest dodawana przez JavaScript. Sprawdź ją na wyrenderowanej stronie.
Warto też sprawdzić zmianę .env.production: skrypt prebuild nadpisuje ten plik, więc może usunąć wcześniej zapisany w nim VITE_BUILD_ID. Nie tłumaczy to braku całej stopki, ale może sprawić, że identyfikator builda przyjmie wartość zapasową ID.
